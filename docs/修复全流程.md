# 努比亚相机修复全流程（HyperOS 4 移植包）

本文记录在 **nubia Z60 Ultra 领先版（NX721J）** 上，让 **努比亚原相机** 在 **HyperOS 4（Android 17）移植包** 中正常启动、录像、防抖的完整过程。内容包含问题现象、根因链、证据、两个模块的实现原理、安装与验证步骤、回滚方式。

> 结论先行：
> 1. 相机启动崩溃 = `Config.getIntValue` 把 `"true"` 当整数解析（`ImmersionMode`）。
> 2. 录像防抖崩溃 = Morpho EIS 库的 GMT 过期自毁校验（SIGILL）。
> 3. 防抖开关不可用 = 顶栏抽屉未初始化（`initAnime` 漏调用），点击闪退（`mShowAnimSet == null`）。
>
> 修复由两个互相独立的模块完成：
> - `CameraMorphoExpiryBypass`（KernelSU / ReSukiSU 模块）：替换一个 vendor 库，解决 SIGILL。
> - `CameraImmersionFix`（LSPosed 模块）：hook 相机 Java 代码，解决启动崩溃与界面问题。

## 1. 设备与 ROM 背景

| 项目 | 值 |
|---|---|
| 机型 | nubia Z60 Ultra 领先版（NX721J） |
| ROM | HyperOS 4 移植包（底包 Xiaomi 14） |
| Android | 17（targetSdk 37） |
| Root | KernelSU Ultra / ReSukiSU |
| Hook 框架 | LSPosed `dev.hyperglass.lsposed` 1.0.2（第三方 fork） |
| 相机包 | 移植包内的 Z80 Ultra 版努比亚相机（`com.android.camera`） |
| 关键路径 | `/vendor/lib64/libmorpho_video_stabilizer.so`、`/data/adb/modules/` |
| 诊断工具 | adb、logcat、tombstone、`uiautomator dump`、androguard（DEX 反编译）、`aapt2` |

移植包把 Z80 Ultra 的相机 APK 与 Z60 Ultra 的配置混在一起，导致两类兼容问题：
- 配置值类型漂移（布尔字符串被当整数）；
- vendor 侧 Morpho 防抖库的授权校验（GMT 截止日期）在移植包中已过期。

## 2. 问题一：相机启动即崩（ImmersionMode）

### 2.1 现象

打开相机立即闪退，`logcat -b crash`：

```
FATAL EXCEPTION: main
java.lang.NumberFormatException: For input string: "true"
    at java.lang.Integer.parseInt(Integer.java:...)
    at cn.nubia.camera.nubiacameraconfig.Config.getIntValue(...)
    at cn.nubia.camera.nubiacameraconfig.Config.getImmersionMode(...)
```

`ActivityManager` 显示 `Process com.android.camera has died`，无 native 崩溃。

### 2.2 根因链

1. 相机启动时读取 `ImmersionMode`，调用 `Config.getIntValue(map, feature, key)`。
2. Z60 Ultra 的 feature 配置里 `ImmersionMode="true"`（布尔字符串）。
3. Z80 Ultra 的相机代码按整数解析（`Integer.parseInt`），抛出 `NumberFormatException`。
4. 异常发生在 `Application.onCreate` 阶段，进程直接死亡，所以“启动即崩”。

### 2.3 证据

- crash buffer 中的完整栈（上方）。
- `aapt2 dump resources` / 反编译确认 feature 默认值 `ImmersionMode="true"`。
- 用其它相机 App（系统相机、第三方）可以正常打开摄像头，排除 HAL/硬件问题。

### 2.4 LSPosed 修复

Hook 点：

```
cn.nubia.camera.nubiacameraconfig.Config#getIntValue(Map, Feature, String)
```

处理规则（`CameraImmersionHook.java`）：

| 输入 | 返回 |
|---|---|
| `"true"` / `Boolean.TRUE` | `1` |
| `"false"` / `Boolean.FALSE` | `0` |
| 合法数字字符串 | 交给原方法 |
| 其它非数字字符串 | Feature 默认值；取不到则 `0` |

关键点：**Map 中没有该 key 时，继续读 `Feature.get(key)` 的默认值并做同样归一化**。这正是 v1.1 → v1.2 的改动：

- v1.1 只处理 Map 中显式存在的 key；
- Z60U 的 `ImmersionMode` 不在 Map 里，走的是 Feature 默认值，v1.1 仍然崩；
- v1.2 增加 Feature 回退分支后解决。

### 2.5 为什么不用改 APK

- 改 APK 需要重签名，会破坏原厂签名与更新链；
- 模块只 hook 一个方法，作用域仅 `com.android.camera`，风险面最小；
- 后续相机更新若修了类型问题，停用模块即可。

## 3. 问题二：Morpho EIS 库 SIGILL（GMT 过期自毁）

### 3.1 现象

相机可以启动、预览，但进入视频/使用防抖时进程被信号杀死：

```
signal 4 (SIGILL), code 1 (ILL_ILLOPC), fault addr 0x...
backtrace:
  #00 pc 0000000000408...
  #01 pc ... libmorpho_video_stabilizer.so (MorphoVideoStabilizer_init+136)
```

`tombstone` / `dropbox` 中可见 `libmorpho_video_stabilizer.so`。

### 3.2 定位过程

1. 从 tombstone 取出故障 PC，映射到 `libmorpho_video_stabilizer.so` 的偏移。
2. 反汇编 `MorphoVideoStabilizer_init`：
   - 调用 `time` / `gmtime_r` 获取当前时间；
   - 与硬编码的 GMT 截止日期比较；
   - 过期后把结果寄存器 `w20` 置 0；
   - 后续通过函数指针表 `br x2` 跳转，但目标地址落在 `.rodata`（内容 `ff ff ff ff`），执行即 SIGILL。
3. 关键寄存器回溯：`w20` 承载校验结果（1=有效，0=过期）。崩溃前 `w20=0`。
4. 校验原始库 SHA-256：`c05691a380479ccd8d7fb78d8e6fec990e8bbe2d907586d2f1edf8fe92e7501b`。

### 3.3 补丁点

文件偏移 `0x408380`：

```
原始：f4 83 45 b9   ; ldr w20, [sp, #0x580]   （读取过期标志，实测为 0）
补丁：34 00 80 52   ; mov w20, #1              （强制“有效”）
```

补丁后 SHA-256：`2fc1ad46d96323e8c04553745069ae251dff9259abb8b4d0c6f877d265f9c554`。

#### 为什么不能只改条件跳转（cset）

- `cset` 只改变条件码赋值，控制流仍会走“过期”分支，最终仍会执行非法 `br x2`；
- 必须在**结果寄存器层面**把“过期”改成“有效”，让后续所有依赖 `w20` 的判断都走正常路径；
- `mov w20,#1` 是最小、最直接的改法。

### 3.4 KSU 模块实现要点

文件：`ksu-module/post-fs-data.sh`

1. **为什么 magic mount 失效**：相机/HAL 通过 vendor 真实路径加载该库，systemless overlay 在该场景未生效。
2. **兜底方案**：`post-fs-data` 阶段（vendor 已挂载）执行
   ```
   mount --bind $MODDIR/system/vendor/lib64/libmorpho_video_stabilizer.so /vendor/lib64/libmorpho_video_stabilizer.so
   ```
3. **SELinux**：bind mount 后 `chcon u:object_r:vendor_file:s0`，否则相机进程无权限。
4. **幂等**：先比对目标 SHA-256，已等于补丁值则跳过；最多等待 30 秒等目标可读。
5. **日志**：`/data/local/tmp/morpho_mount.log`，记录 start/current/mount rc/after/done。
6. **卸载**：模块不修改其它文件，删除模块并重启即恢复。

## 4. 问题三：防抖抽屉未初始化

### 4.1 现象

- 视频模式点击手型（防抖）图标，相机闪退：
  ```
  NullPointerException
    at cn.nubia.camera.street.NubiaPopupDrawerButton.playShowAnim(NubiaPopupDrawerButton.java:600)
  ```
- 修复闪退后发现“防抖开关点不到”：手型图标只能展开/收起抽屉，而抽屉根本没出现。

### 4.2 根因

- `NubiaPopupDrawerButton` 只是抽屉的开关按钮，真正防抖开关是 `VideoMemberFragment.mAntiShakeSwitch`（`ZteSwitcherButtonWithTitle`）。
- `TopBarFragment.initNubiaPopupDrawerButton(button, Z)` **没有**调用 `initAnime`；只有 `BottomBarFragment` 的版本调用了 `initAnime(list, RelativeLayout)`。
- 结果：顶栏按钮的 `mDrawerParent / mAnimeItems / mShowAnimSet` 全为 null，抽屉未 inflate。
- 点击时 `playShowAnim()` 执行 `mShowAnimSet.start()` → NPE。

### 4.3 修复

1. **防闪退**：hook `playShowAnim()V` before，`mShowAnimSet == null` 时 `setResult(null)` 短路。
2. **补抽屉初始化**：hook `NubiaPopupDrawerButton.initialize(...)` after，仅对 `pref_antishake_key` 的按钮：
   - 宿主取 `TopBarFragment.mTopBarParent`（`R.id.topbar` 的 RelativeLayout）；
   - `View.post` 等按钮挂载后调用 `initAnime(new ArrayList(), host)`；
   - `TopBarFragment.initNubiaPopupDrawerButton` after 再兜底一次（幂等）。
3. **位置**：抽屉左边缘 = 按钮左边界（紧贴闪光灯图标），垂直中线对齐（`topMargin = 按钮中线 − 抽屉高度/2`）；抽屉展开后才测得到高度，因此 `playShowAnim` after post 一帧重算。
4. **交互**：
   - 展开时隐藏手型图标；
   - 点击抽屉外区域（`dispatchTouchEvent` 判定，不影响原事件）或开始录像时收起，并恢复图标；
   - 展开期间临时隐藏抽屉右侧的分辨率/帧率文字与镜头图标，避免重叠（三档完整可点）。
5. **模式切换**：若 `mDrawerParent` 仍 attach，重新计算位置；否则走完整初始化。

## 5. 界面微调

全部通过 LSPosed hook 实现，竖屏生效，横屏保持原厂布局。

| 项目 | 目标 | 实现 |
|---|---|---|
| 底部三键（快门/相册/前后摄） | 上移 42dp | `BottomBarFragment.initBottomPanelLayout` after，`mBottomLayout.bottomMargin += 42dp` |
| 模式切换栏 | 上移 31dp | `ActivityBase.initMemberScrollerUI` after，`mCameraSelect.bottomMargin += 31dp` |
| 人文街拍右侧设置按钮 | 与快门平齐 | `StreetFragment.setHighSettingVisible` after，`mStreetEffectLayout.bottomMargin += 42dp` |
| 专业模式“专业视频”按钮 | 与快门平齐 | `ProFragment.initModePicker` after，`mode_picker_button_layout.bottomMargin += 42dp` |
| 录像中三图标 | 保持同一高度 | `VideoFragment.onVideoStartBegin` after，两套录制布局各 +42dp |
| 防抖抽屉 | 按钮右侧、同高、不遮挡 | 见第 4 节 |

幂等处理：用 `WeakHashMap<View, Integer>` 记录每个 View 上次设置后的 margin，系统重设后再叠加，重复回调不累积。

> 注意：v2.0 曾给 `mHighSettingLayout` 加 42dp，导致专业模式参数行（S/WB/ISO/EV/连拍）被抬高；v2.2 已移除该偏移，专业按钮改由 `mode_picker_button_layout` 单独上移。

## 6. 安装步骤

### 6.1 前置条件

- 已安装 KernelSU Ultra / ReSukiSU，并授权 root；
- 已安装 LSPosed（本机为 `dev.hyperglass.lsposed` 1.0.2）；
- 从移植包提取原始相机 APK 备份（可选，便于回滚）。

### 6.2 安装 KSU 模块（先装）

1. 在 KernelSU/ReSukiSU 管理器中安装 `CameraMorphoExpiryBypass-v1.2.zip`。
2. **重启手机**（`post-fs-data.sh` 只在开机阶段执行）。
3. 开机后检查日志：
   ```
   adb shell su -c 'cat /data/local/tmp/morpho_mount.log'
   ```
   期望末尾出现 `done ok`，且 `after=2fc1ad46...c554`。

### 6.3 安装 LSPosed 模块（后装）

1. `adb install -r CameraImmersionFix-LSPosed-v2.4.apk`
2. 打开 LSPosed 管理器 → 模块 → 启用 `Camera Immersion Fix`。
3. 作用域勾选 `com.android.camera`（Manifest 已声明，通常自动带入）。
4. **强制停止相机**（覆盖安装模块后必须做，否则复用旧进程，hook 不生效）：
   ```
   adb shell am force-stop com.android.camera
   ```
5. 打开相机。

## 8. 回滚与风险

### 8.1 回滚

| 目标 | 操作 |
|---|---|
| 回滚到上一版 LSPosed 模块 | 覆盖安装对应旧版 APK，强停相机 |
| 停用全部 Java 修复 | LSPosed 中停用模块（或卸载），强停相机/重启 |
| 恢复 Morpho 原库 | KernelSU 中删除 `morpho_expiry_bypass` 模块，重启 |
| 恢复相机原版 | 卸载 LSPosed 模块 + KSU 模块，重启；重新安装备份的相机 APK |

### 8.2 风险

- **ROM/相机升级后偏移失效**：Morpho 补丁依赖固定文件偏移 `0x408380` 与原始库 SHA；库一变，补丁必须重新定位并校验。
- **签名**：LSPosed 模块用本地 debug key 签名（证书 SHA-256 `0310b334...cdf3`），换 key 后覆盖安装需先卸载。
- **LSPosed fork 兼容性**：`dev.hyperglass.lsposed` 为第三方 fork，legacy Xposed API 在 Android 17 上的行为需实机验证。
- **布局偏移**：42dp/31dp 基于 1116×2480、density 3.0 校准；换机型或分辨率需重测。
- **未吞异常原则**：所有 hook 独立 try/catch，只记录日志，不吞目标方法自身的非空指针异常。

## 9. 已知限制

1. 界面微调仅竖屏生效，横屏保持原厂布局（避免误伤）。
2. 抽屉避让采用“临时隐藏右侧组件”，不是重新排布；展开瞬间右侧会有短暂空白。
3. `getIntValue` 只归一化布尔与常见非数字；若后续出现其它类型漂移，需要扩展。
4. 录像中三图标与未开拍时仍有约 12dp 的固有差异（来自录制布局自身的 margin 基线），未强行抹平。
5. 本方案不修改 ROM、不修改相机 APK，仅通过 KSU bind mount 与 LSPosed hook 生效。

```powershell
cd lsposed-module
```

```bash
python ksu-module/build_module.py
```
